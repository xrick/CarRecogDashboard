## 先理解一個核心比喻

整件事可以想成這個場景：

- **那台相機** = 一棟大樓的門禁警衛室，裡面有一本「可以放行的車牌名冊」。
- **我們要寫的程式** = 一個「遙控小幫手」，可以隔空看名冊、加車牌、改車牌、刪車牌。
- **那本 1023 頁的 PDF** = 警衛室的「對講機使用說明書」，超厚、簡體中文、大部分用不到。
- **HTTP Digest 認證** = 跟警衛對話前要先對「通關暗號」，暗號錯了警衛直接不理你。
- **我（Claude）** = 你請來的翻譯兼工人。

而你今天用的那些 `/sc:xxx` 指令，每一個都像是**給我的一張「任務卡」，卡片背面印著我必須遵守的規矩**。我每次都先看規矩，再動手。

## 第二章：`/sc:troubleshoot`（沒有 --fix）— 「醫生只能先看診，不能直接開刀」

**我做了什麼（比喻）**：

## 第三章：`/sc:troubleshoot --fix` ×3 — 「這次准你開刀，但開刀前要簽同意書」

接下來你連續三次用了 `--fix`。這張卡的規矩變成：
> **可以動手改，但改之前要先說明、取得你同意，改完要驗證。**

於是我像外科醫生，每次都「先講解要怎麼開 → 等你點頭 → 才下刀 → 縫合後檢查」。三場手術分別是：

### 手術一：裝上「行車記錄器」
相機講話我們都聽不到，怎麼除錯？我幫程式裝了三樣東西：

- **行車記錄器**（把每次跟相機的對話內容印出來）——這樣下次出事看得到現場。
- **容忍相機的爛憑證**（這種相機的「身分證」都是自己亂發的，程式以前太龜毛不接受，現在放寬）。
- **先敲門再說**（連線時先打一個「哈囉你在嗎」的萬用招呼，幾乎每台相機都聽得懂，用來區分「是門沒開」還是「是對方聽不懂這句話」）。

### 手術二：修好「上菜順序錯亂」
裝了記錄器後發現一個怪現象：敲門成功了，但接下來該做的事沒發生。

**比喻**：餐廳廚房做完一道菜，服務生卻在「還沒把鍋子收走」之前就衝去點下一道菜，結果系統以為廚房還在忙，把新訂單擋掉了。我把順序改成「**先收鍋子、再點下一道**」，連鎖流程就通了。

### 手術三：發現相機講的是「古代方言」
敲門成功，但一講到「給我看名冊」，相機回「**Bad Request（你在公三小）**」。

**比喻**：我們一直用「現代標準國語」跟相機講話（這是說明書主推的新版講法），但這台老相機（型號 XC-204BLPR，晶片很舊）其實只聽得懂「**古代方言**」。我回頭翻說明書第 10.3 章，找到了方言版的講法，然後做了一個聰明設計：

> **帶兩位翻譯一起去**。先讓「現代國語翻譯」上場，如果相機聽不懂（回 400），**自動換「方言翻譯」接手**，使用者完全不用管。

我還寫了一個「**方言解讀器**」(`_parse_kv`)——因為方言版相機回話的格式很特別（像在念一封制式公文：`第0筆.車牌=ABC123`），得有人把它翻譯回正常資料。我用說明書的範例先驗證過這個解讀器能用。

**我做了什麼（比喻）**：
像驗屋師傅拿手電筒到處照，但**不准動工**。我給了你一份分級報告：

- ✅ **好消息**：房子骨架通了、之前的掀桌 bug 真的修好了、「空名冊」這個情況處理正確。
- 🔴 **高風險**：三個「寫入」動作（加車牌、改車牌、刪車牌）目前**完全不檢查相機的回應**——萬一相機說「我沒加成功」，程式還是會跟你說「成功了！」。這像郵差說「我有送到」但其實沒送，你卻不知道。
- 🔴 **高風險**：名冊「**有資料**」時長什麼樣，我們**一次都還沒看過**。空名冊跑通不代表有資料時跑得通。
- 🟡 **中風險**：名冊很多筆時只會抓前面一頁，後面的會默默看不到。

我**沒有改任何程式**，只給你排好優先順序的建議——因為規矩不允許動工。

## 規矩對照表（我每張任務卡都遵守了哪條界線）

| 你下的指令 | 卡片背面的規矩 | 我實際做的 |
|---|---|---|
| `/sc:brainstorm` | 先釐清需求再動手 | 翻 PDF + 問你 4 個問題後才寫程式 |

## 我們現在站在哪裡

```
[需求確認] → [第一版程式] → [連不上→診斷] → [修：記錄器+敲門]
   → [修：上菜順序] → [發現講方言→雙翻譯自動切換]
   → [崩潰→修：出菜口] → [✅ 端到端跑通，名冊目前 0 筆]
   → 👉 你在這裡
```

**白話版現況**：遙控小幫手已經能成功連上相機、自動切換到方言模式、正確讀出「名冊目前是空的」，而且不會再崩潰。

**還沒驗證的（下一步最該做的）**：
名冊「**有車牌時**」長什麼樣、以及「**加一筆車牌**」相機到底有沒有真的加進去。這兩件事只能用「真資料」驗證——建議你在相機上加一筆假車牌（例如 `TEST001`），把程式 log 裡那兩行原始回應貼回來，我才能確定「方言解讀器」不用改、或知道怎麼改。

在那之前，任何對「寫入」功能的修補都會是「閉著眼睛改」，我不建議貿然動工。
