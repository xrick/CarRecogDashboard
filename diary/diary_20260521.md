## 2. RTSP 整合方式

RTSP **不走 HTTP API**，是另一條獨立的影像串流通道。整合分前後端兩段：

### 2.1 後端：URL 組合與配發

| 角色 | 程式位置 | 行為 |
|---|---|---|
| URL 樣板 | [`CameraConfig.rtsp_url`](../src/backend/config.py#L51-L56) | 套規格 §4.1.1：`rtsp://{user}:{pwd}@{host}:554/cam/realmonitor?channel={N}&subtype={M}` |
| 子碼流預設 | `rtsp_subtype: int = 1` | 子碼流（sub-stream），減輕多路解碼負擔 |
| 公開端點 | [`GET /dashboard/sites/{site_id}/cameras`](../src/backend/app.py#L144-L158) | 回傳 `{site_id, host, channel, subtype, role, kind, rtsp_url}` 清單給前端 |

後端**不參與 RTSP 播放**，只負責把 URL 透過 REST API 提供給前端。

### 2.2 前端：cv2 + PyQt5 播放面板

唯一播放實作在 [src/frontend/rtsp_panel.py](../src/frontend/rtsp_panel.py)（223 行），核心策略：

| 議題 | 設計 | 程式位置 |
|---|---|---|
| 取流 | `cv2.VideoCapture(url, cv2.CAP_FFMPEG)` + 強制 RTSP-over-TCP | [rtsp_panel.py:70-72](../src/frontend/rtsp_panel.py#L70-L72) |
| 為何 TCP | UDP 易撕裂幀；TCP 較穩 | 引自 [claudedocs/rtsp_viewer_說明文件.md](../claudedocs/rtsp_viewer_說明文件.md) |
| 設定參數 | `OPENCV_FFMPEG_CAPTURE_OPTIONS = "rtsp_transport;tcp"` | [rtsp_panel.py:70](../src/frontend/rtsp_panel.py#L70) |
| 執行緒模型 | `RtspWorker(QThread)` 拉幀，`pyqtSignal` 送回 GUI | [rtsp_panel.py:65-97](../src/frontend/rtsp_panel.py#L65-L97) |
| **cv2 / PyQt5 plugin 衝突** | cv2 延遲匯入（先 pop `QT_QPA_PLATFORM_PLUGIN_PATH`），再還原 PyQt5 plugin path | [rtsp_panel.py:24-49](../src/frontend/rtsp_panel.py#L24-L49) |
| 多路 grid | `urls = [c.get("rtsp_url", "") for c in cams ...]` 動態建 `QGridLayout` | [rtsp_panel.py:176](../src/frontend/rtsp_panel.py#L176) |
| Simulate 模式 fallback | 顯示「未設定相機」訊息，不開 cv2 | [rtsp_panel.py:162](../src/frontend/rtsp_panel.py#L162) |

### 2.3 RTSP 資料流

```
 ┌─────────────────┐                ┌─────────────────┐                ┌──────────────────┐
 │ Dahua 相機      │  RTSP/TCP 554  │ 前端 cv2 worker │  pyqtSignal    │ PyQt5 RtspPanel  │
 │ (主/子碼流)     │  ─────────────►│ (QThread)       │  ─────────────►│ (QGridLayout)    │
 └─────────────────┘                └─────────────────┘                └──────────────────┘
        ▲
        │ 後端只負責給 URL：
        │ GET /dashboard/sites/{id}/cameras → rtsp_url
        │ (config.CameraConfig.rtsp_url 樣板)
```

**注意**：後端從不解碼 RTSP，事件流走 `eventManager.attach`（HTTP），影像流走 RTSP（前端直連相機）。兩條完全分離。

## 3. NVR 整合狀況

### 3.1 結論：**完全未整合**

### 3.2 為什麼沒有

目前整個架構是「**前端工地相機直連 → eventManager 推事件 → ingest 寫入本地 SQLite**」單層拓樸，不經過 NVR：

```
 ┌────────────┐    eventManager.attach(HTTP)    ┌──────────────┐
 │ ANPR 相機  │ ──────────────────────────────► │ ingest.py    │ ─► SQLite
 │ XC-204BLPR │    RTSP(直連)                    │ camera_client│
 └────────────┘ ──────────────────────────────► └──────────────┘
        │
        └─► 前端 rtsp_panel.py 也直連相機 (非經 NVR)
```

[config.py](../src/backend/config.py) 的 `CameraConfig` 是「**一台相機 = 一筆設定**」，沒有 `nvr_host` 之類欄位；[ingest.py](../src/backend/ingest.py) 為每個 `CameraConfig` 開一條 `CameraClient` 連線，也是直連模型。

### 3.3 若要整合 NVR，需新增的東西

雖然非本次稽核範圍，但供日後參考：

| 需求 | 大華對應 API 章節 | 變更範圍 |
|---|---|---|
| 列出 NVR 上的相機 | `§4.5.2 LogicDeviceManager.getCameraAll` | 新增 `NvrClient` 類別 |
| 取 NVR 錄影檔索引 | `§4.10 mediaFileFind` (factory.create / findFile / findNextFile / close) | 新增錄影檔查詢 endpoint |
| 點播歷史影像 | `§4.11 RTSP playback URL`: `rtsp://...//cam/playback?channel=N&starttime=...&endtime=...` | 擴充 `CameraConfig` 加 `nvr_host`、`channel_on_nvr` |
| 訂閱 NVR 上的事件 | NVR 通常也支援 `eventManager.attach`，但 codes 與單機相機略異 | 多打一個 host 即可 |

## A. 觀念釐清：什麼是「NVR 相關 API」

V3.87 沒有獨立的「NVR 章節」，因為大華 NVR 與單機 IPC 共用同一套 HTTP API（同樣的 cgi-bin、同樣的 Digest 認證）。**差別在於 NVR 多了「多通道管理」與「歷史錄影查詢」兩塊能力**：

| 能力 | 單機 IPC | NVR |
|---|---|---|
| 即時影像 (RTSP `realmonitor`) | ✅ 1 個 channel | ✅ N 個 channel |
| 即時事件 (eventManager.attach) | ✅ | ✅ |
| 名單管理 (recordFinder / VehicleRegisterDB) | ✅ | ✅ |
| 添加 / 移除子相機 (LogicDeviceManager) | ❌ | ✅ **NVR 特有** |
| 子通道線上 / 錄影狀態 | ❌ | ✅ **NVR 特有** |
| 歷史錄影 / 截圖查詢 (mediaFileFind) | ⚠️ 限 SD 卡 | ✅ **NVR 主場** |
| RTSP 回放 (`cam/playback`) | ⚠️ 限 SD 卡 | ✅ **NVR 主場** |
| 錄像時間範圍查詢 (storage.getBoundTime) | ⚠️ | ✅ |

下面分四群整理：**(B) 多通道管理 → (C) 歷史錄影查詢 → (D) 回放/下載 → (E) 仍可共用的事件/名單 API**。

## B. 多通道管理（NVR 特有）

### B1. §4.6.23 添加攝像頭到 NVR 指定通道

| 屬性 | 值 |
|---|---|
| URL | `POST /cgi-bin/LogicDeviceManager.cgi?action=addCameraByGroup` |
| Body | JSON `{"group":[{"DeviceInfo":{"UserName","Password","ProtocolType","Port","Address"},"cameras":[{"uniqueChannel":N}]}]}` |
| ProtocolType 取值 | `Private` / `Dahua2` / `Dahua3` / `General` / `Onvif` / `GB28181` / `Ehome` |
| 預設 Port | RTSP=554、HTTP=80、Private=37777 |

用途：把一台子相機掛到 NVR 的指定 unique channel 下。

### B2. §4.6.24 按組刪除視頻通道

`POST /cgi-bin/api/LogicDeviceManager/deleteCameraByGroup` body `{"group":[{"DeviceID":"DH12345678910","uniqueChannels":[1,2,3]}]}`（`uniqueChannels=[-1]` 表示刪除該 DeviceID 下所有通道）

### B3. §4.6.25 獲取所有可用視頻源（**列出 NVR 上所有子相機**）

| 屬性 | 值 |
|---|---|
| URL | `GET /cgi-bin/LogicDeviceManager.cgi?action=getCameraAll` |
| 回傳 | `camera[i].ControlID / Name / Enable / DeviceInfo.{Address,Port,UserName,Password,ProtocolType,SoftwareVersion} / VideoStream / Channel / UniqueChannel / Type{Local\|Remote\|...}` |
| 重點欄位 | `Type=Remote` 即「掛在 NVR 上的遠端相機」；`UniqueChannel` 是 NVR 內部唯一編號 |

這是設計 dashboard「相機清單」UI 時的關鍵 API — 一次拿到 NVR 上所有 ANPR 相機的位址、登入、軟體版本。

### B4. §4.6.26 訂閱設備上下線狀態

`POST /cgi-bin/api/LogicDeviceManager/attachCameraState` body `{"channel":[1,2],"heartbeat":10}` → 回 multipart `{"channel":1,"connectionState":"Connected\|Connecting\|Unconnect\|Empty\|Disable\|Changed\|Hibernation"}`。

當 NVR 上的子相機斷線時即時推送，比輪詢省事。

### B5. §4.6.29 獲取通道線上狀態

`POST /cgi-bin/api/LogicDeviceManager/getCameraState` body `{"uniqueChannels":[-1]}` → `{"states":[{"channel":0,"connectionState":"Connected","errorMessage":"LoginConnectFailed\|UserOrPwdNotValid\|LoginConnectTimeout\|..."}]}`

一次性查詢（非訂閱）。診斷子相機掉線原因用。

### B6. §4.6.30 獲取通道錄像狀態

`POST /cgi-bin/api/recordManager/getStateAll` 空 body → `{"state":[{"Main":{"State":1},"Extra1":{...},"Extra2":{...},"Extra3":{...}}]}`

知道每個通道、每個碼流是否正在錄影。

## C. 歷史錄影 / 截圖查詢（NVR 主場）

V3.87 把這塊統一在 `§4.10 錄像`，採「**5 步驟有狀態查詢**」模式：

```
factory.create → findFile (with conditions) → findNextFile (paginated, max 100) → close → destroy
                  └─ §4.10.5 通用 / §4.10.6-13 按事件類型加 DB 過濾
```

### C1. §4.10.5 查找媒體文件（通用）

```
Step 1  GET  /cgi-bin/mediaFileFind.cgi?action=factory.create
        → result=08137   (objectId)

Step 2  GET  /cgi-bin/mediaFileFind.cgi?action=findFile
              &object=08137
              &condition.Channel=1
              &condition.StartTime=2014-1-1 12:00:00
              &condition.EndTime=2015-1-10 12:00:00
              &condition.Types[0]=dav
              &condition.Events[0]=AlarmLocal
              &condition.Events[1]=VideoMotion
              &condition.VideoStream=Main
              &condition.Dirs[0]=/mnt/dvr/sda0
              &condition.Flags[0]=Timing     # Timing|Manual|Marker|Event|Mosaic|Cutout
              &condition.Tag=tag123
        → OK

Step 3  GET  /cgi-bin/mediaFileFind.cgi?action=findNextFile&object=08137&count=100
        → found=N + items[]
            items[i].Channel / StartTime / EndTime / Type(dav|jpg|mp4)
                    / Events[] / VideoStream / FilePath / Length / Duration / Tag

Step 4  GET  /cgi-bin/mediaFileFind.cgi?action=close&object=08137
Step 5  GET  /cgi-bin/mediaFileFind.cgi?action=destroy&object=08137
```

### C2. 按事件型態查找 — 同樣的 5 步流程，差別在 condition 多一層 DB 過濾

| § | 事件型態 | DB 過濾鍵 | 可過濾欄位 |
|---|---|---|---|
| §4.10.6 | FaceDetection（人臉**偵測**） | `DB.FaceDetectionRecordFilter` | ImageType / Sex / Age[range] / Glasses / Mask / Beard |
| §4.10.7 | FaceRecognition（人臉**辨識**） | `DB.FaceRecognitionRecordFilter` | Person.{Name,Sex,Birthday,Country,Province,City,CertificateType,ID,GroupID,Age[]} / Glasses / Mask / Beard / GroupID[] / SimilaryRange[] |
| §4.10.8 | HumanTrait（人體特徵） | `DB.HumanTraitRecordFilter` | HumanAttributes.{CoatColor[],CoatType[],TrousersColor[],TrousersType[],HasHat,HasBag,Sex,Age[],HairStyle} |
| **§4.10.9** | **TrafficCar**（**車牌抓拍**） | `DB.TrafficCar` | **PlateNumber / PlateType / PlateColor / VehicleColor / Speed / Event / Country**，皆採 `<compare condition>` 格式：`["==","*888"]`、`["||","TrafficGate","Alarm*"]`、`["<>",40,80]`（範圍內）、`["><",40,80]`（範圍外） |
| §4.10.10 | IVS（智能視訊分析） | `DB.IVS` | Rule(`CrossLineDetection / CrossRegionDetection / LeftDetection / WanderDetection / ...`) / Action(`Appear / Disappear / Inside / Cross`) / ObjectType(`Human / Vehicle / NonMotor`) |
| §4.10.11 | NonMotor（非機動車） | `DB.NonMotorRecordFilter` | NumOfCycling / Color / ... |
| §4.10.12 | WorkClothesDetection（工裝） | `DB.WorkClothesRecordFilter` | — |
| §4.10.13 | AnimalDetection | `DB.AnimalDetectionRecordFilter` | — |

> **這個專案最相關的就是 §4.10.9 TrafficCar**：可依車牌、車速、車牌顏色、事件類型（TrafficJunction / TrafficGate / Alarm）做歷史查詢。回傳項目含 `Summary.TrafficCar.{PlateNumber,PlateType,PlateColor,VehicleColor,Country,Speed,Event}` + `FilePath`（NVR 上的 JPEG 路徑）。

### C4. §4.10.15 獲取錄像時間範圍

## D. 回放 / 下載

### D1. §4.1.2 RTSP 回放媒體流（按時間）

```
rtsp://<server>:554/cam/playback?channel=N
    &starttime=2012_09_15_12_37_05         # 或 starttimeRealUTC=2012_09_15_04_37_05 (UTC)
    &endtime=2012_09_15_18_34_14           # 或 endtimeRealUTC=...
```

DESCRIBE / SETUP / PLAY / PAUSE / TEARDOWN 流程與即時流相同。

### D2. §4.1.3 RTSP 檔案流（按檔名）

```
rtsp://<server>:554/<path_to_filename>
# 例：rtsp://192.168.1.108:554/mnt/sd/2015-09-16/001/dav/20/20.32.08-20.32.28[M][0@0][0].dav
```

檔名從 §4.10 mediaFileFind 拿到的 `items[i].FilePath` 取得。

### D3. §4.1.5 創建 RTSP 鑑權 Token

`POST /cgi-bin/api/TokenManager/createToken` body `{"Channel":0}` → `{"Token":"AwDSEci0j4EUW6pUz5bcQ0yK8_..."}`

讓客戶端不必每次都帶 Digest 認證；有些 RTSP 播放器不支援 Digest，需走 Token。

### D4. §4.10.16 / §4.10.17 / §4.10.18 / §4.10.19 — 檔案下載

| § | URL | 用途 |
|---|---|---|
| §4.10.16 | `GET /cgi-bin/RPC_Loadfile/<filename>` | 按檔名下載（filename 從 mediaFileFind 取得）；回傳 `application/octet-stream` 二進位 |
| §4.10.17 | `GET /cgi-bin/loadfile.cgi?action=startLoad&channel=N&startTime=...&endTime=...&subtype=0&Types=dav` | **按時間範圍下載錄像** (`.dav`) |
| §4.10.18 | `GET /cgi-bin/RecordStreamInterleaved.cgi?action=attachStream&path=...&password=...` | 加密下載 |
| **§4.10.19** | `GET /cgi-bin/loadfile.cgi?action=downPicByTime&channel=N&startTime=...&endTime=...&Types=jpg&Flags=*` | **按時間範圍下載交通抓拍 JPEG（含元資料）** |

**§4.10.19 是車辨專案的金礦**：回應是 `multipart/x-mixed-replace`，每個 part 含：
```json
{
  "filedata": {
    "info": {
      "plateNum": "12345",
      "Speed": 60,
      "UTC": 1465389120,
      "UTCMS": 550,
      "address": "xxx jiedao"
    }
  }
}
```
緊接著一段 `image/jpeg` binary。**一個 HTTP request 就能批量取得時間區間內所有車牌抓拍（含車牌、車速、時間戳、地點 + 圖檔）** — 比 §4.10.9 mediaFileFind 5 步流程簡單很多，但只回 JPEG 沒回 dav 影片。

## G. 給整合 NVR 的最小路徑（4 個 API 起手）

如果只是想「**把 NVR 上的歷史車牌資料拉進 dashboard**」，最小可行整合：

1. **§4.6.25** `getCameraAll` — 一次列出 NVR 上所有 ANPR 相機 → 填到 [config.py](../src/backend/config.py) 或自動發現
2. **§4.10.15** `storage.getBoundTime` — 知道每個通道有錄影的時段範圍
3. **§4.10.19** `loadfile.cgi?action=downPicByTime` — **直接拿時間區間內所有車牌抓拍 JPEG + plateNum/Speed/UTC/address**，省掉 §4.10.5 5 步流程
4. **§4.1.5** `TokenManager.createToken` + **§4.1.2** `cam/playback` — 點某筆歷史紀錄時，能 RTSP 回放當下影片

進階再加：
- **§4.6.26** `attachCameraState`（子相機掉線即時告警）
- **§4.10.9** `mediaFileFind` + TrafficCar 過濾（複雜查詢：「車牌含 888 且車速 40-80 km/h 的所有抓拍」）
- **§4.10.17** `startLoad`（下載完整 .dav 錄影檔，存證用）

## H. 後續建議

1. **不要急著做 NVR 整合**：目前架構（相機直連）對 demo 與小型工地完全夠用。NVR 整合的真正價值在「**歷史回查 + 多相機集中管理**」。
2. **若要做，先選 §4.10.19**：CP 值最高，一個 API 就能讓 dashboard 多出「歷史車牌查詢」功能。
3. **`CameraConfig` schema 需重構**：目前是「host = 相機」；NVR 模式下 `host = NVR`、相機是其下的 `uniqueChannel`。這是 breaking change，要做就趁專案早期。
4. **本附錄已涵蓋規格書 V3.87 所有 NVR 相關章節**：日後不需再從規格書翻找，直接 grep 此檔即可。
